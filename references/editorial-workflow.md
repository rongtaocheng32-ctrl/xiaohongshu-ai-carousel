# Editorial workflow

## 1. Diagnose the source pool

Extract:

- claims that can be checked;
- opinions and analogies;
- the reader problem being solved;
- novelty for an AI-curious beginner;
- ambiguity or multiple meanings;
- details that distract from the main idea.

Do not summarize everything. Decide what deserves a post.

## 2. Rank candidate topics

Score each candidate from 1–5 on:

1. beginner relevance;
2. clarity of one core takeaway;
3. practical usefulness;
4. visual explainability;
5. factual confidence;
6. save/share potential.

Recommend the strongest topic and explain the tradeoff. Split the source into a series when two ideas need different reader promises.

## 3. Choose a story pattern

- Concept: familiar misconception → correct definition → mechanism → example → boundary.
- Knowledge fragment: surprising fact → explanation → consequence → memory hook.
- Comparison: shared goal → critical difference → side-by-side example → when each fits.
- Mechanism: problem → components → loop → output → failure modes.
- Misconception: common belief → correction → cause → practical rule.
- Tutorial: scenario → prerequisites → steps → example → cautions.

## 4. Plan the carousel

Every page needs one job:

1. Cover: promise a useful distinction.
2. Tension: show why the reader's current mental model is incomplete.
3. Model: explain the essential components.
4. Mechanism: show how the system behaves over time.
5. Example: ground the abstraction in one task.
6. Boundary: prevent overgeneralization and close with a memory line.

Compress or expand this pattern to fit the topic. Do not pad pages.

## 5. Fact-check

- Search before writing factual technology content.
- Prefer original technical documentation, standards, papers, and source authors.
- Use multiple independent sources for contested or fast-changing claims.
- Preserve the difference between a product-specific definition and a general industry definition.
- Paraphrase sources; use short quotations only when the wording itself matters.
- Record links during research so the final explanation can be defended.

## 6. Write for beginners

- Use everyday verbs before specialist nouns.
- Prefer “判断、行动、观察、调整” to anthropomorphic claims about human-like thought.
- Use one example throughout a mechanism page when possible.
- State limits near the capability claim, not as an afterthought.
- Keep headings concrete and short enough for mobile reading.
